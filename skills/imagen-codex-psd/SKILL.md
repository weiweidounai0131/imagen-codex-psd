# 单张海报转可编辑 PSD

开始时先说明最终会得到分层 PSD：一张完整背景、可编辑的文字，以及确实需要单独恢复的可移动素材。用户选择 A“拆出全部主文案”或 B“只拆指定文案”；局部模式只清除并重建用户选中的文字，其他文字和插画标签仍留在背景中。背景复杂或含插画内文字时，需要用户检查结果，不能承诺逐像素复原。

按 [references/workflow.md](references/workflow.md) 顺序执行。面向用户只说明本步用途、会看到的结果和下一步；不展示脚本、账本、OCR 或图层字段等开发术语。只有确实缺少选择或输入时才请用户行动；正常阶段不要反复确认。句式见 [references/progress-templates.md](references/progress-templates.md)。

1. **输入与拆字范围。** 只接受一张 PNG/JPEG/WebP。确认尺寸、画布和工作目录；运行 `scripts/doctor.py` 检查依赖与 OCR 凭证。用户已请求海报转换且未指定本地/保密处理时，必要的 PaddleOCR 阶段已包含在转换授权中；首次提交前简短说明图片会发送给第三方服务，不再重复询问同一授权。用户明确要求本地/保密处理时改用本地路线。若缺少凭证，只询问一次是申请并通过 Keychain 安全录入、稍后继续，还是选择手工录入；具体路径见 [references/ocr-setup.md](references/ocr-setup.md)。绝不要求用户把 token 粘贴到聊天。

   对新 run，在 OCR 或背景处理前调用当前会话提供的 `functions.request_user_input_async`，只展示 A“拆出全部主文案”与 B“只拆指定文案”。必须等到用户真实选择，再运行 `scripts/selection_gate.py record-mode` 记录范围。若选择控件返回 pending/queued、超时或没有答案，保持 `pending_mode`，不运行 OCR；仅当目标会话确实没有该工具时，才在普通对话中询问并等待回答。收到 B 后先告知：接下来会盘点图片里的文字并生成编号图，用户看到编号图后再选择要拆的数字；此时不要要求用户抄文案或提供尚不存在的编号。历史 run 按其保存的版本与选择状态继续。

2. **OCR 与文字盘点。** 用户选择范围后，恢复同一原图已有的 OCR 任务；没有任务时只提交一次。若提交状态不明，停止自动重投。对照整张源图校对文字、位置和语境，修正错字与合并框，并补录清晰可见的漏字。区分读者看到的主文案与图示内部标签；无法判断的项保持待核对。完成后生成审定文字清单；软件绑定和完整性校验不能代替实际看图。

3. **局部文字选择。** 完整模式在文字盘点后直接进入背景阶段。局部模式仅给审定的主文案编号，并展示编号图和简短摘录；插画内文字不编号。展示编号图后，用当前会话的 `functions.request_user_input_async` 提供 A“按编号选择”与 B“想拆的文字未被标记，发送截图”，同一题允许直接输入编号（如 `1,3`）。如果用户直接回复数字，按原样记录方法和编号并继续，不再二次确认；如果只选 A，再请用户直接回复编号。选择 B 后请用户在普通对话附上一张圈选目标的截图，并映射回原图。截图分支一次绑定一个目标；精确位置或文案不明时保持待核对，匹配已有文字时复用原记录，避免重复图层。
4. **整图背景。** 使用一次完整画布清字生成，不按文本框把原图和 donor 矩形拼贴。完整模式清除 plan 标记的主文案；局部模式提示词必须逐字列出选中项待清除，并明确列出账本中所有未选主文案、全部插画内文字和人工补录项需保留的原文与位置。提示词参考 [references/imagegen-prompts.md](references/imagegen-prompts.md)。把候选背景与原图整图对照，不能只看缩小整图就下“全部保留”结论；按账本逐项放大对应源区域与候选区域并排核对，特别检查 OCR 漏项和相似标题在不同位置的文字。真实记录选中文字是否消失、每项未选文案和插画标签是否保留及位置是否匹配，并检查框、人物、装饰、标志和关系线是否位移。局部模式的接受记录必须逐项完整列出未选账本 ID、原文、源框，以及 `visible_in_source`、`retained_in_clean_base`、`position_matches_source` 真实视觉结论，并记录插画内文字身份检查。缺项、false 或 pending 都拒绝接受。`prepare_stage3.py` 会重新打开绑定的接受记录并复核这份清单。真实视觉确认不能由 JSON 自我声明替代；执行 agent 记录真实 reviewer、差异和绑定哈希，没有真实视觉确认就不能写 PASS。一轮候选不合格就报告具体差异并停止，不启动局部擦除或阈值循环。
5. **必要的前景例外。** 先列全所有确实从干净背景缺失的对象，再按每板最多九项分组生成稀疏素材板；不要默认每个图标单独生成一张。仅复杂标题、空间不足或无法分清单元格时单独开板并说明原因。只重做未通过的对象/小组，保留已接受素材。只为已记录、确实从干净背景缺失的对象创建透明独立资产；背景仍是完整画布。使用 [references/asset-exceptions.md](references/asset-exceptions.md)、[references/imagegen-prompts.md](references/imagegen-prompts.md) 与随包 chroma/alpha 处理脚本。核对 ID、单元格、原图定位框和每个独立 alpha 的来源；不拆出全部插画。
6. **原生文字与 PSD。** 按 [references/artifact-contracts.md](references/artifact-contracts.md) 建立样式计划；一个选中的主文案 ID 可用 `style_runs` 在同一原生 Type 层中表达多颜色、字号和字重，片段必须按原文顺序完整覆盖文字。每项都要对照源图实际文字行审查角度，不能把省略的角度当作水平通过。OCR四角框只给角度建议，多点轮廓完整保留但不用于猜角。同一文字层的所有片段共用父项的布局框和变换；独立文字层只有共用同一行基线时才共享角度和锚点。当前仅支持 `vertical_alignment=top`；居中需要 Photoshop 原生编辑/重排验收后再实现，不用缓存位移或 `SpaceBefore` 模拟。原生 `ParagraphRun` 按每个 CR 分段，段落范围包含该 CR 且 `SpaceBefore=0`。局部模式中 `prepare_stage3.py` 会再核对 selection gate 哈希，并拒绝把任何未选 ID 写成 Type 层。绑定接受的背景、文字计划、零个或多个标题审查文件和前景清单；调用本包内 `stage3_writer_adapter.py`。脚本不会依赖另一个已安装 Skill 的绝对路径。
7. **结构与视觉验收。** 用 psd-tools 重开 PSD，检查画布、组、原生 Type 图层、文案/字体属性、变换框和各素材唯一性；查看完整预览与局部上下文。报告自动检查结果和不确定项。用户还需在 Photoshop 手动打开、双击编辑文字、移动/缩放素材、保存、关闭并重开；没有用户确认前状态保持 `PENDING_MANUAL_PHOTOSHOP`。

## 运行要求

依赖和本机字体见 [README.md](README.md)。该压缩包不会自动安装依赖或覆盖全局 Skill；先在隔离环境安装 `requirements.txt`。字体使用本机 Source Han Sans CN，不随包分发。内置 ImageGen 通过当前 Codex 提供的图像工具调用，不配置私有 API Key。

任何哈希绑定失效、主文案文字不全、背景结构明显错位、例外素材没有来源、Type 图层溢出或 Photoshop 手动测试未完成，都必须在交付状态中如实标记，不能以“PSD 已生成”代替验收。
